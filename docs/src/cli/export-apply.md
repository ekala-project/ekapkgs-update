# export & apply - LLM Integration

The `export` and `apply` commands enable LLM-assisted debugging by exporting failure context and applying AI-generated fixes.

## Synopsis

```bash
# Export failure context for LLM analysis
ekapkgs-update export [OPTIONS] <ATTR_PATH>

# Apply LLM-generated fix
ekapkgs-update apply [OPTIONS] <ATTR_PATH>
```

## Description

### export

Exports comprehensive failure context in a format suitable for LLM analysis:
- Error details and logs
- Package metadata
- Source code context
- Build output
- Suggested fixes

### apply

Applies fixes generated by LLMs or other tools:
- Patch files (unified diff format)
- Structured JSON changes
- Validates changes by building
- Optionally resumes the update workflow

## export Command

### Synopsis

```bash
ekapkgs-update export [OPTIONS] <ATTR_PATH>
```

### Arguments

**`<ATTR_PATH>`**

Package attribute path to export.

```bash
ekapkgs-update export python312Packages.requests
```

### Options

#### `--database <PATH>` (short: `-d`)
Path to SQLite database.

**Default:** `~/.cache/ekapkgs-update/db.sqlite3`

```bash
ekapkgs-update export --database /var/lib/ekapkgs-update/db.sqlite3 mypackage
```

#### `--format <FORMAT>`
Export format: `json` or `markdown`.

**Default:** `json`

```bash
# JSON format (machine-readable, structured)
ekapkgs-update export mypackage --format json

# Markdown format (human-readable, LLM-friendly)
ekapkgs-update export mypackage --format markdown
```

#### `--output <PATH>` (short: `-o`)
Output file (writes to stdout if not specified).

```bash
# Write to file
ekapkgs-update export mypackage --format markdown --output context.md

# Write to stdout
ekapkgs-update export mypackage --format json

# Pipe to other tools
ekapkgs-update export mypackage --format json | jq '.error'
```

## apply Command

### Synopsis

```bash
ekapkgs-update apply [OPTIONS] <ATTR_PATH>
```

### Arguments

**`<ATTR_PATH>`**

Package attribute path to apply fix to.

```bash
ekapkgs-update apply python312Packages.requests --patch fix.patch
```

### Options

#### `--database <PATH>` (short: `-d`)
Path to SQLite database.

**Default:** `~/.cache/ekapkgs-update/db.sqlite3`

```bash
ekapkgs-update apply --database /var/lib/ekapkgs-update/db.sqlite3 mypackage --patch fix.patch
```

#### `--patch <PATH>`
Patch file to apply (unified diff format).

```bash
ekapkgs-update apply mypackage --patch fix.patch
```

**Patch format:** Standard unified diff
```diff
--- a/pkgs/python-modules/requests/default.nix
+++ b/pkgs/python-modules/requests/default.nix
@@ -10,7 +10,6 @@
   };

   patches = [
-    ./patches/fix-tests.patch
   ];

   meta = with lib; {
```

#### `--changes-json <PATH>`
JSON file with structured changes.

```bash
ekapkgs-update apply mypackage --changes-json changes.json
```

**JSON format:**
```json
{
  "files": {
    "pkgs/python-modules/requests/default.nix": {
      "operations": [
        {
          "type": "remove_line",
          "line": 13,
          "content": "    ./patches/fix-tests.patch"
        },
        {
          "type": "replace",
          "from": "doCheck = true;",
          "to": "doCheck = false;"
        }
      ]
    }
  }
}
```

#### `--validate`
Validate changes by building.

```bash
ekapkgs-update apply mypackage --patch fix.patch --validate
```

When enabled:
- Applies the changes
- Builds the package
- Rolls back if build fails
- Preserves if build succeeds

#### `--resume`
Resume update workflow after applying fix.

```bash
ekapkgs-update apply mypackage --patch fix.patch --resume
```

When enabled:
- Applies the fix
- Validates by building (automatic)
- Continues the update workflow:
  - Runs tests (if configured)
  - Creates commit (if configured)
  - Creates PR (if configured)

### Examples

```bash
# Simple apply
ekapkgs-update apply mypackage --patch fix.patch

# Apply and validate
ekapkgs-update apply mypackage --patch fix.patch --validate

# Apply and resume update workflow
ekapkgs-update apply mypackage --patch fix.patch --resume

# Apply JSON changes
ekapkgs-update apply mypackage --changes-json changes.json --validate

# Apply with both patch and JSON
ekapkgs-update apply mypackage --patch fix.patch --changes-json extras.json --resume
```

## Complete Workflow

### 1. Update Fails

```bash
ekapkgs-update update python312Packages.requests --preserve-failures --commit
# ... fails ...
```

### 2. Export Context

```bash
ekapkgs-update export python312Packages.requests \
  --format markdown \
  --output context.md

# Review context.md
cat context.md
```

### 3. Get LLM Fix

```
# Copy context.md to ChatGPT/Claude/etc.
# Prompt: "This Nix package update failed. Please analyze the error and provide a fix as a unified diff patch."
# LLM generates fix.patch
```

### 4. Apply Fix

```bash
ekapkgs-update apply python312Packages.requests \
  --patch fix.patch \
  --resume
```

### 5. Verify

```bash
# Check if update succeeded
ekapkgs-update query --package "python312Packages.requests" --status success

# Or inspect if still failed
ekapkgs-update inspect python312Packages.requests
```

## Integration with LLMs

### ChatGPT/Claude

```bash
# 1. Export
ekapkgs-update export mypackage --format markdown > context.md

# 2. Provide to LLM with prompt:
cat > prompt.txt << 'EOF'
This Nix package update failed. Please analyze the error and provide:
1. Root cause analysis
2. A fix as a unified diff patch
3. Explanation of the fix

Here's the failure context:
EOF
cat context.md >> prompt.txt

# 3. Copy prompt.txt to LLM interface

# 4. Save LLM's patch to fix.patch

# 5. Apply
ekapkgs-update apply mypackage --patch fix.patch --resume
```

### GitHub Copilot

```bash
# 1. Export and open in editor
ekapkgs-update export mypackage --format markdown --output context.md
code context.md  # or vim, etc.

# 2. Navigate to worktree
cd /tmp/ekapkgs-update-worktrees/mypackage

# 3. Open problematic file
code pkgs/mypackage/default.nix

# 4. Use Copilot to suggest fixes based on error context

# 5. Save changes and create patch
git diff > fix.patch

# 6. Apply
ekapkgs-update apply mypackage --patch fix.patch --resume
```

### Programmatic LLM APIs

```python
import subprocess
import openai
import json

# 1. Export context
context = subprocess.check_output([
    "ekapkgs-update", "export", "mypackage", "--format", "markdown"
]).decode()

# 2. Query LLM
response = openai.ChatCompletion.create(
    model="gpt-4",
    messages=[
        {"role": "system", "content": "You are a Nix package expert."},
        {"role": "user", "content": f"Fix this package update failure:\n\n{context}"}
    ]
)

# 3. Extract patch from response
patch = extract_patch_from_response(response)
with open("fix.patch", "w") as f:
    f.write(patch)

# 4. Apply
subprocess.run([
    "ekapkgs-update", "apply", "mypackage",
    "--patch", "fix.patch",
    "--resume"
])
```

## Common Patterns

### Patch Fixes

```bash
# Remove outdated patch
cat > remove-patch.patch << 'EOF'
--- a/pkgs/mypackage/default.nix
+++ b/pkgs/mypackage/default.nix
@@ -10,7 +10,6 @@
   };

   patches = [
-    ./patches/outdated.patch
   ];
EOF

ekapkgs-update apply mypackage --patch remove-patch.patch --resume
```

### Dependency Fixes

```bash
# Add missing build dependency
cat > add-dep.patch << 'EOF'
--- a/pkgs/mypackage/default.nix
+++ b/pkgs/mypackage/default.nix
@@ -5,6 +5,7 @@
   buildInputs = [
     foo
     bar
+    newdep
   ];
EOF

ekapkgs-update apply mypackage --patch add-dep.patch --validate
```

### Test Fixes

```bash
# Disable failing tests
cat > disable-tests.patch << 'EOF'
--- a/pkgs/mypackage/default.nix
+++ b/pkgs/mypackage/default.nix
@@ -12,7 +12,7 @@
   };

-  doCheck = true;
+  doCheck = false;
EOF

ekapkgs-update apply mypackage --patch disable-tests.patch --resume
```

## Limitations

### Patch Application

- Patches must apply cleanly to worktree
- Use `--validate` to test before committing
- Failed patches don't modify worktree

### Worktree Required

- Requires preserved worktree from `--preserve-failures`
- Worktree must not be stale
- Check with `worktrees show` first

### LLM Accuracy

- Always validate LLM-generated patches
- Review patches before applying
- Test builds in isolated environment first
- Use `--validate` flag

## Exit Codes

- `0` - Command succeeded
- `1` - Export/apply failed
- `2` - Invalid arguments
